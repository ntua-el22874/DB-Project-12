# Εξαμηνιαία Εργασία Βάσεων Δεδομένων 2025-2026
**Σύστημα Διαχείρισης Γενικού Νοσοκομείου «Υγειόπολις»**
**Ομάδα 12**

Σε αυτόν τον φάκελο βρίσκεται όλος ο κώδικας (DDL, DML, Triggers, Queries) για την εργασία του μαθήματος, όπου σχεδιάσαμε και υλοποιήσαμε τη βάση δεδομένων για το νοσοκομείο "Υγειόπολις". Επειδή στην εκφώνηση υπήρχαν κάποιες λεπτομέρειες που αφήνονταν πάνω μας, πήραμε συγκεκριμένες σχεδιαστικές αποφάσεις και κάναμε ορισμένες παραδοχές για να διασφαλίσουμε ότι το σύστημα θα δουλεύει όσο πιο ρεαλιστικά και σωστά γίνεται.

## 1. Σχεδιαστικές Επιλογές & Παραδοχές
- **Μοντελοποίηση Προσωπικού (Ιεραρχία):** Για να αποφύγουμε την επανάληψη δεδομένων (π.χ. να γράφουμε όνομα, τηλέφωνο και email σε 3 διαφορετικούς πίνακες), φτιάξαμε έναν κεντρικό πίνακα `Staff` με τα βασικά στοιχεία όλων των εργαζομένων. Οι γιατροί, οι νοσηλευτές και οι διοικητικοί "σπάνε" στους δικούς τους ξεχωριστούς πίνακες (`Doctor`, `Nurse`, `AdminStaff`), όπου κρατάμε μόνο τα εξειδικευμένα χαρακτηριστικά τους (π.χ. άδεια ιατρικού συλλόγου). 
- **Υποχρεωτικά Πεδία:** Θεωρήσαμε ότι σχεδόν όλα τα βασικά πεδία στους πίνακες (όπως ημερομηνίες, ονόματα, amka) είναι υποχρεωτικά (NOT NULL) εκτός από κάποιες εξαιρέσεις (π.χ. ημερομηνία εξιτηρίου για κάποιον που νοσηλεύεται ακόμα).
- **Ειδικότητες Γιατρών:** Εφόσον δεν μας δόθηκε έτοιμη λίστα, ορίσαμε εμείς μια τυπική λίστα ιατρικών ειδικοτήτων (π.χ. ΙΑΤΡΟΣ_ΕΠΕΙΓΟΝΤΩΝ_ΠΕΡΙΣΤΑΤΙΚΩΝ, ΚΑΡΔΙΟΛΟΓΟΣ, ΧΕΙΡΟΥΡΓΟΣ, ΠΑΙΔΙΑΤΡΟΣ κλπ.) για να μπορούμε να γεμίσουμε ρεαλιστικά τα test δεδομένα μας.
- **Κανόνες Εποπτείας Γιατρών:** Κάθε γιατρός μπορεί να επιβλέπεται από κάποιον άλλο γιατρό. Βάλαμε σαν κανόνα ότι οι ειδικευόμενοι ('RESIDENT') είναι υποχρεωτικό να έχουν επόπτη, ενώ αντίθετα οι διευθυντές ('DIRECTOR') είναι στην κορυφή της ιεραρχίας και απαγορεύεται να έχουν. Παράλληλα υποθέσαμε ότι κάθε διευθυντής μπορεί να είναι υπεύθυνος το πολύ σε 1 τμήμα (department).
- **Χρεώσεις ΚΕΝ:** Για τον υπολογισμό του τελικού κόστους μιας νοσηλείας, το σύστημα βάζει πρόσθετη χρέωση στον ασθενή ΜΟΝΟ όταν οι συνολικές ημέρες παραμονής του στο νοσοκομείο ξεπεράσουν τη Μέση Διάρκεια Νοσηλείας που ορίζεται από τον αντίστοιχο κωδικό ΚΕΝ.

## 2. Έλεγχος Ακεραιότητας Δεδομένων (Triggers)
Για να διασφαλίσουμε ότι δεν θα μπαίνουν λανθασμένα δεδομένα στη βάση (είτε από λάθος του χρήστη είτε επίτηδες), ρίξαμε αρκετό βάρος στη δημιουργία Triggers. **Πολύ σημαντικό: όλα τα triggers τρέχουν τόσο στα INSERT όσο και στα UPDATE**. Αυτό σημαίνει ότι κανένας δεν μπορεί να "ξεγελάσει" το σύστημα αλλάζοντας απλά μια παλιά εγγραφή (π.χ. κάνοντας update την ώρα ενός χειρουργείου).

Αναλυτικά οι κανόνες που επιβάλλονται με τα triggers:
1. **Ασφάλεια Ασθενών (Αλλεργίες):** Όταν πάει να συνταγογραφηθεί ένα νέο φάρμακο, το σύστημα βρίσκει πρώτα (μέσω του `hosp_id`) σε ποιον ασθενή ανήκει η νοσηλεία. Μετά σκανάρει όλες τις δραστικές ουσίες αυτού του φαρμάκου. Αν ο ασθενής έχει αλλεργία σε έστω και μία από αυτές, η εντολή ακυρώνεται με error.
2. **Έλεγχος 8ωρης Ανάπαυσης & Συνεχόμενων Βαρδιών:** Αυτός ο κανόνας υλοποιήθηκε αρκετά έξυπνα. Το trigger ψάχνει αν ο εργαζόμενος πήρε την απαιτούμενη ξεκούραση. Επιτρέπονται 2 βάρδιες την ίδια μέρα ΜΟΝΟ αν απέχουν 8 ώρες (π.χ. Πρωί και μετά Νύχτα). Επίσης το trigger "πιάνει" και την αλλαγή ημέρας, μπλοκάροντας κάποιον που έκανε Νυχτερινή (που λήγει στις 07:00) από το να δουλέψει Πρωινή την επόμενη μέρα, μιας και το κενό ξεκούρασης είναι 0 ώρες. Φυσικά απαγορεύεται να κλειστεί κάποιος σε 2 τμήματα την ίδια ώρα.
3. **Όρια Βαρδιών ανά Μήνα:** Μπλοκάρονται αυτόματα αναθέσεις βαρδιών αν κάποιος ξεπεράσει το όριο στον ίδιο μήνα. Συγκεκριμένα: Γιατροί max 15, Νοσηλευτές max 20, Διοικητικοί max 25.
4. **Νυχτερινές Βάρδιες:** Απαγορεύεται αυστηρά ένας εργαζόμενος να κάνει πάνω από 3 συνεχόμενες νυχτερινές βάρδιες.
5. **Διαχείριση Χειρουργείων & Επεμβάσεων:** - Δεν επιτρέπεται ποτέ η ίδια αίθουσα (`room`) να κλειστεί για 2 διαφορετικές επεμβάσεις που πέφτουν την ίδια ώρα.
   - Δεν επιτρέπεται ο ίδιος γιατρός να συμμετέχει σε 2 επεμβάσεις που επικαλύπτονται χρονικά.
6. **Διαθεσιμότητα Κλινών:** Για να μπει κάποιος σε μια κλίνη (`bed`), αυτή πρέπει να έχει τη σήμανση 'FREE'. Διαφορετικά απορρίπτεται η εισαγωγή.
7. **Αυτο-εποπτεία:** Μπλοκάρεται η περίπτωση όπου κατά λάθος πάει να οριστεί κάποιος γιατρός ως επόπτης του εαυτού του.

## 3. Ευρετήρια και Βελτιστοποίηση (Indexes)
Για τη βελτιστοποίηση της απόδοσης των ερωτημάτων και την αποφυγή καθυστερήσεων κατά τις συνδέσεις (JOINs) και τις ομαδοποιήσεις, σχεδιάσαμε και εφαρμόσαμε μια στοχευμένη στρατηγική ευρετηρίων στο αρχείο `indexes.sql`:
- **Σύνθετα Ευρετήρια σε Πίνακες Μεγάλου Όγκου:** Στον πίνακα `Hospitalization`, ο οποίος δέχεται τον μεγαλύτερο φόρτο, δημιουργήσαμε σύνθετα ευρετήρια (π.χ. συνδυασμό `ken_code` και `discharge_date` ή `patient_id` και `dept_name`). Αυτό επιτρέπει τη δραστική μείωση του χρόνου εκτέλεσης στα απαιτητικά queries (Q1, Q3, Q6, Q14) αποφεύγοντας τις πλήρεις σαρώσεις πινάκων (full table scans).
- **Ευρετηρίαση Πινάκων Συσχέτισης:** Σε πίνακες-γέφυρες που δέχονται συνεχή JOINs, όπως οι `ProcedureParticipation`, `Prescription` και `DrugSubstance`, ορίσαμε ευρετήρια στα ξένα κλειδιά και σε στήλες ελέγχου (όπως ο ρόλος του χειρουργού), εξασφαλίζοντας άμεση απόκριση.
- **Αποφυγή Πλεονασμού:** Αποφύγαμε τη δημιουργία ευρετηρίων σε στήλες που αποτελούν Πρωτεύοντα Κλειδιά (Primary Keys), καθώς το σύστημα διαχείρισης τα ευρετηριάζει αυτόματα, διατηρώντας τη βάση ελαφριά κατά τις εισαγωγές (INSERTs).

## 4. Οδηγίες Εκτέλεσης (Πώς να τρέξετε την εργασία)
Για να στηθεί η βάση σωστά από το μηδέν, τα αρχεία πρέπει να τρέξουν με την παρακάτω σειρά:

1. **`install.sql`**: Είναι το κυρίως DDL αρχείο. Αρχικά απενεργοποιεί τους ελέγχους (`SET FOREIGN_KEY_CHECKS = 0`) για να σβήσει τυχόν παλιούς πίνακες, και στη συνέχεια τους χτίζει όλους ξανά, ορίζοντας τα Primary και Foreign Keys.
2. **`load.sql`**: Αυτό το script εισάγει αυτόματα τα δεδομένα από τα αρχεία CSV (`*_Clean.csv`) στους αντίστοιχους πίνακες της βάσης δεδομένων.
3. **`Triggers.sql`**: Εδώ βρίσκονται όλοι οι κανόνες ασφαλείας που εξηγήσαμε παραπάνω. Το τρέχετε για να "θωρακίσετε" το σύστημα.
4. **`indexes.sql`**: Ενεργοποιεί τα ευρετήρια για τη βελτιστοποίηση των αναζητήσεων.
5. Τέλος, μπορείτε να τρέξετε τα αρχεία .sql που περιέχουν τα ζητούμενα 15 ερωτήματα-queries (Q1 έως Q15) της εκφώνησης για να δείτε τα αποτελέσματα.
